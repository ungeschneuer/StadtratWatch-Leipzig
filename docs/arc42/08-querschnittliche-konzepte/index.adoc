= Querschnittliche Konzepte
:icons: font

== Fachliches Datenmodell

Die Wahlperiode (`registry.json`) führt Sitzungen, Personen, Fraktionen und Parteien. Eine Person hat Mitgliedschaften in Fraktionen und Parteien mit Zeiträumen; Auswertungen rechnen mit der Zugehörigkeit am Sitzungstag. „Partei“ ist in Leipzig die Wahlliste 2024, solange keine Quelle einen Wechsel belegt. Eine Abstimmung (`SessionScanItem`) hat Gegenstand (TOP, Drucksache, Titel, Typ, Einreichende, `paperUrl`), Stimmen je Person und optional `reviewStatus`.

== Datengewinnung und Qualität

Siehe <<adr-0009,ADR-0009>>. Statusgrößen: `verified`, `corrected`, `reviewed` und ohne Kennzeichnung veröffentlicht; `provisional` und `needs-review` mit Kennzeichnung; `discarded` und `skipped` nicht veröffentlicht.

== Abrufe bei den Quellen

Die Skripte fragen jede Quelle mit einem User-Agent, der das Projekt nennt, und mit einer Pause zwischen zwei Anfragen. Was schon erfasst ist, wird nicht erneut geholt: Vorlagen kennt `papers.json`, Abstimmungen liest `leipzig-votings` nur aus neuen Aufzeichnungen. Die täglich nötigen OParl-Listen (Personen, Mitgliedschaften, Organisationen) holt `leipzig-members` über `modified_since` nur mit den seit dem letzten Lauf geänderten Objekten und führt sie mit dem Stand des letzten Laufs zusammen; die Bewerberliste fragt es mit `If-None-Match` und `If-Modified-Since` ab. Den Stand hält ein Cache von GitHub Actions (`.cache/leipzig-sources`), nicht das Repository. Fehlt der Cache oder ist der letzte vollständige Abruf eine Woche alt, wird alles neu geladen; so wirkt sich ein Objekt, dessen Änderungsdatum der Server nicht nachführt, höchstens eine Woche aus.

== Sicherheit und Datenschutz

* Keine Cookies, kein Tracking, keine Inhalte Dritter auf der Seite.
* Prüfende nutzen eigene GitHub-Tokens, die im Browser bleiben; Schreibrechte steuert GitHub.
* Personenbezogene Daten nur von Mandatsträger:innen und Verwaltungsspitze aus öffentlichen Sitzungen; Einwohner:innen werden nicht veröffentlicht.

== Basispfad

Die Seite kann unter einem Pfad liegen. Server-seitige Links nutzen `sitePath()`, Alpine-Ausdrücke `window.sitePath()`, Tabs ändern nur die Query.
