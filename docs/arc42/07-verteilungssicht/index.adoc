[#verteilungssicht]
= Verteilungssicht
:icons: font

[cols="1,3",options="header"]
|===
| Knoten | Inhalt

| GitHub-Repository
| Code (`main`), Daten (`data/leipzig-8` auf `main`, offene Änderungen auf den Daten-Branches), Issues, Pull Requests.

| GitHub Actions
| `ci.yml` (Prüfungen), `deploy.yml` (Seite und Prüfoberfläche), `leipzig-recordings`, `leipzig-members`, `leipzig-votings`, `leipzig-review-recheck`, `leipzig-review-reminder`, `leipzig-data-publish`.

| GitHub Pages
| `https://<owner>.github.io/<repository>/`: die Astro-Seite; `/review/` die Prüfoberfläche; `404.html` leitet Deep-Links der Prüfoberfläche weiter.

| GitHub Releases
| `evidence-<datum>`: Zitatbilder aller veröffentlichten Abstimmungen, Tafelbilder der Prüffälle. `deploy.yml` lädt die Zitatbilder nach `public/evidence/`, die Seite liefert sie selbst aus.

| Server des Betreibers
| ALLRIS-Runner `minutes-runner/` als täglicher Cronjob auf einem Server des Betreibers (alternativ systemd-Timer): holt amtliche Ergebnisse und Verlaufsprotokolle aus ALLRIS und pusht sie mit einem Deploy-Key auf `data/leipzig-votings`. ALLRIS nimmt von GitHub Actions keine Verbindung an (geprüft 12.11.2026: Verbindungsaufbau läuft in den Timeout, alle anderen Quellen antworten); in Actions gibt der ALLRIS-Client deshalb nach dem ersten Timeout für den Rest des Laufs auf.

| Rechner des Betreibers
| Nur für Ausnahmen: lokales Whisper für Sitzungen ohne Untertitel (`docs/guides/leipzig-whisper.md`).
|===

Build-Variablen der Seite: `SITE_URL`, `SITE_BASE`, `DATA_REPOSITORY`, `DATA_PULL_REQUEST_URL`, optional `DEFAULT_PARLIAMENT_PERIOD` (Standard `leipzig-8`).
